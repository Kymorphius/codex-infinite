# 0020：通过 Hermes 所属接口共享记忆与任务上下文

状态：采用，2026-09-10。

Hermes 的共享 GPT 会话仍由原生前端执行。复制 Hermes 记忆到原生会话数据库，
或切换执行引擎以获得记忆工具，会造成来源不清、会话分叉和配置相互覆盖。

采用 Hermes 项目中的专用 stdio MCP，调用 Hermes 原生记忆入口及只读历史、
任务上下文接口。配置目录在启动时固定，原生 GPT 保持自身会话和工具执行权限。
记忆按需作为工具结果读取，不重写既有会话的系统提示词或缓存前缀。

写入只在用户授权范围内通过 Hermes 正式记忆工具执行，保留现有写入审批设置。
看板完成结果仍由已绑定原始回合的 worker 收回，不让 MCP 任意改变卡片执行状态。
原生会话索引保持只读；没有新增网络端口或放宽任何现有安全不变量。

代价：工具配置需要在每台机器上独立连接；旧会话可能需要原生工具刷新。
本阶段不能代表 Hermes 外部记忆 provider、自动技能学习或远程执行已等价接入。

启动配置的来源只负责首次初始化。增强版前端已经存在的 `config.toml` 由其自身
管理，后续启动不得再用源配置整体覆盖。包装层仅移除自身管理的根级上下文容量
覆盖项，以保持按会话设置容量的既有行为。这使 MCP 注册、插件刷新与模型选择
可以跨重启保留；源前端后续配置不会再隐式覆盖独立前端。
