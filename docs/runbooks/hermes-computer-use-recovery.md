# Hermes 共享会话的桌面控制恢复

## 症状与原因

2026-09-10，Hermes 共享会话可以调用原前端的联网插件，但桌面控制返回
`Trusted RPC service is not configured: sky`。

增强版前端使用独立的 `CODEX_HOME`。其 bundled marketplace 曾指向另一配置目录，
导致本机已经安装的 Computer Use 插件没有被正确纳入当前前端能力配置。
修正插件来源并刷新后，既有会话仍可能持有旧 MCP 进程；只重置 Node 内核或重载
MCP 配置，不保证释放该会话已缓存的工具实例。

## 恢复原则

1. 核对实际运行前端的配置目录，备份后只修正错误的 marketplace 来源。
   不复制其他前端的凭据、身份或完整配置。
2. 使用当前前端自身的插件配置刷新流程，重新生成同一配置目录下的工具环境。
   核对 Computer Use 插件可用，以及桌面服务路径与当前配置目录一致。
3. 对空闲且明确属于本次验证的会话释放旧运行实例并重新加载。
   本次采用临时归档、恢复，再显式恢复运行实例；会话 UUID 和历史保持不变。
   不对正在运行的任务操作，不为单个旧实例问题重启全部前端。
4. 从 Hermes 输入框发送实际测试请求，验证原前端执行工具以及 Hermes 收到结果。
   单独的进程存在、插件列表或服务注册不构成完成证据。

## 本次验证

从 Hermes 的已有共享会话发送计算器测试，原前端通过 `mcp__node_repl__js`
加载官方 `@oai/sky`，读取实际窗口后点击全部清除、1、7、乘、2、3、等于。
工具回执标记 `computerUse`，界面读回表达式 `17×23` 和结果 `391`；
Hermes 收到同一回合的完成答复，计算器结果窗口保留。

此外，Hermes renderer 将提交失败提示标记为本地提交错误，仅在同一会话的后续
提交被后端接受后清理。真实执行错误继续保留，失败的重试也不会清理提示。
对应修复位于 Hermes 项目；类型检查、84 项针对性测试和 renderer 构建通过。
安装后的 Personal Panel 已加载新 renderer，并通过实际输入和发送按钮复测：
在测试会话设置已知原生草稿使提交冲突，确认错误出现；按草稿版本清除测试草稿后
重试，收到正常答复且原错误消失。安装后的应用签名验证通过。
Control Console 的 `npm run check` 和 573 项测试通过。

本机配置备份、会话转录和生成的应用资源含运行状态，不纳入 Git。
