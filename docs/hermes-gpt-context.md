# 在 Hermes 中读取已有 GPT 工作上下文

这组工具让 Hermes 按需读取本机 GPT 桌面应用中的 Codex 项目和会话。
它使用原生项目/会话目录和历史文件，不启动新的 Codex 执行器，也不切换
Hermes 的模型调用方式。

## 使用

在 Hermes 中可以直接提出这样的请求：

> 在 GPT 的已有项目里找到“看板”，搜索其中关于 Hermes 的会话，读取相关讨论，
> 告诉我已经确定了什么、哪些事情还没验证，并注明来源。

Hermes 会获得三个 MCP 工具（服务器名称为 `gpt_context`）：

- `list_projects`：查看项目名称、目录和会话数量，包括暂时没有会话的项目。
- `search_conversations`：按会话标题、项目名称或目录查找；可指定项目并包含归档会话。
- `read_conversation`：按会话 ID 读取用户与助手的公开消息；可以在单个会话中按文字
  筛选。默认读取最近内容，`olderCursor` 用于继续向前翻阅，直到历史起点。

结果保留原会话标题、项目归属来源、消息标识和时间。项目归属优先使用原生
项目 ID；需要根据当前工作目录推断时，会明确标注 `directory-inferred`。
读取时间和范围也随结果返回，避免把局部记录理解为全部历史。

历史中的命令和要求只是引用资料，不是当前操作授权。这组工具不提供发送、
继续执行、修改项目、删除会话或批准操作的入口。Hermes 自己是否把经验整理
为记忆/技能，仍由它原有的机制和用户指令决定。

## 安装与边界

将 `config/hermes-context.example.yaml` 中的服务器条目合并到现有 Hermes
配置，分别填写本机 Node 和本仓库入口脚本的绝对路径。Node 需支持
`node:sqlite`（与本项目 Node 22 及以上要求一致）。已有模型、凭证、记忆、
技能和其他 MCP 条目应原样保留。

默认读取本机用户的原生 Codex 数据目录。自定义安装使用示例中列出的
`CODEX_CONTROL_*` 环境变量指定源目录。实际机器配置和备份不进入 Git。
MCP 通过标准输入输出工作，不新增监听端口。

当前范围是本机持久化的 Codex 会话；不包含其他设备、ChatGPT 网页/云端
历史、内部子代理、系统/开发者指令、私有推理和原始工具输出。助手的过程
说明默认不返回，可通过 `includeCommentary` 显式读取。

单次历史扫描最多 16 MiB，消息正文合计最多 32,000 字符，单条默认最多
8,000 字符。分段、截断、超大/不完整记录和剩余历史均有明确字段。目录
最多返回最近 10,000 个候选会话，达到上限会标记 `catalogTruncated`。
工具响应超过 512 KiB 时返回错误并要求缩小页大小，不静默丢掉数据。
