# 原生任务完成后的 Hermes 后台技能复盘

## 行为

原生 GPT 继续执行看板主任务。卡片经确认进入 Done 后，Hermes 在独立进程调用
自身的后台技能复盘入口，使用 Hermes 当前模型与辅助复盘配置。不是再向原会话
发送一条复盘消息，也不把复盘提示写入原生历史。

仅复盘已完成、执行引擎为 external 的卡片。Review、失败、中断、未明确完成的
任务不触发。采用配置 `kanban.background_learning.enabled` 和 `boards` 白名单，
默认关闭；启用后不追溯旧卡片。每个完成版本只创建一份持久作业，未知结果不自动
重跑。任务重新打开后再完成构成新的版本。

## 所属机制

- 使用 Hermes 原生 `spawn_background_review_thread` 构造复盘并在独立进程执行。
  工具白名单和技能来源标记由原生复盘机制维护；仅启用 skills，内置和外部记忆
  均不参与。本阶段不接入外部记忆 provider。
- 使用已完成任务正文与已接受的成果作为输入，不抓取整个会话或私有推理。
  过长上下文明确跳过，不截断后声称已完整复盘。
- 自动技能仍受 Hermes 后台归属保护：不接管用户、内置、hub 或固定技能。
  原有技能写入审批规则保持；自动生成的技能按原生 provenance 记录。
- 学习作业保存状态和实际成功动作摘要。无可复用经验时允许无变化完成；模型或
  凭证错误为失败，进程意外终止为结果未知，不假装成功或自动再次写入。
- 提供只读 MCP `hermes_learning_status` 查询本 profile 作业，避免把后台复盘
  混进原会话。无需新端口、定时任务或复制登录身份。

## 验证

隔离 profile 真实调用原生后台复盘，确认生成技能有 agent 来源，未写生产技能、
记忆或原会话。测试完成事件过滤、看板白名单、去重、重新完成、任务状态变化、
进程失败与只读状态。通过真实看板完成事件触发并读取作业结果。保持现有会话和
未提交工作，完成 Hermes 针对性测试及 Control Console 检查后本地提交。
