# 主动切换本机会话后定位最新轮次

## 问题与目标

本机实测从短会话切回长会话时，原生时间线先接近底部，约 1.5 秒后在轮次列表挂载时恢复到旧阅读位置（反向时间线 `scrollTop=-4077`），并持续停留。用户主要阅读最新内容，明确切换会话应在原生恢复完成后落到最新轮次。

## 行为边界

- 只响应用户通过增强页签、最近会话或原生本机会话侧栏发起的切换；启动、页面重建、自动同步和同一会话内继续阅读不强制滚动。
- 目标身份以已挂载的本机 `data-above-composer-conversation-id` 为准；旧会话、被后续切换取代的请求、超时请求都不能滚动当前时间线。
- 目标时间线挂载后立即按反向或普通时间线的实际方向锚定最新；切换期间捕获该时间线的滚动事件，同步纠正迟到的原生位置恢复，不等待旧位置稳定后再纠正。定位有明确时限，不持续轮询。
- 用户在切换后滚轮、触摸、点击或键入即取消自动定位；不读写消息、草稿、轮次或批注，不关闭任何增强功能。

## 验证

- 单元测试覆盖迟到恢复、快切换、用户主动操作、同会话和普通/反向时间线。
- `npm run check` 与 `npm test` 通过；本机真实切换复测旧位置不会在稳定后保留，且入口、批注与草稿仍在。Windows 本回合不部署。

## 本机验收记录

- 修复前同路径复现：切回约 1.5 秒后时间线停在 `scrollTop=-4077`，4 秒后仍未返回最新。
- 修复后同路径复测：约 1.5 秒原生时间线短暂跳到 `-4705`；约 1.9 秒被校正到 `-52`，5.4 秒后仍在最新一轮附近，导航计时器已结束。
- 即时锚定版再次走相同的短会话→长会话路径，约每 40–50 毫秒采样 7 秒（129 个样本）：目标会话加载后从 `0` 到 `-26`、`-52`，没有采到旧位置大幅负值；结束仍在 `-52`，锚定计时器已结束。该采样验证可见状态，不等于证明原生内部不再尝试恢复旧位置。
- 原会话、未发送草稿状态、四个控制台入口、批注面板及固定页签样式均已读回；没有在 Windows 部署。
