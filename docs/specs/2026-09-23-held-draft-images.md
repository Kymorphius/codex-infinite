# 存待办保留图片草稿

## 问题与目标

原生输入框的“存待办”目前只保存文字。带图片的草稿因此会生成缺少图片的待办；纯图片草稿甚至无法触发保存。修复后，待办管理必须能显示图片数量，且恢复发送时重新附带原图。

## 数据与安全边界

- 仅处理当前原生 composer surface 内可读取的图片预览。最多 8 张；验证 PNG、JPEG、GIF 或 WebP 文件头，单张不超过 8 MiB，总量不超过 24 MiB。不确定或不可读取时整条保存失败，不留下缺图待办。
- 图片 Blob 保存在同一原生渲染器的设备本地 IndexedDB；localStorage 待办记录只存图片引用、文字及既有时间/来源字段。不得把会失效的 blob URL 当作持久引用，也不得把图片字节写进 localStorage。
- 先持久化全部图片，再写入待办记录。若待办记录写入失败，尽力删除刚存的图片，原输入框保持不变。恢复前必须读取全部图片；任一图片缺失即停止，不发送也不删除待办。
- 恢复时将图片重建为 app-server `image` 输入，并沿用现有“先加入队列，再删除待办”的顺序。删除待办后清理其图片 Blob；清理失败不能重新执行消息。
- 不猜测原生附件移除按钮。保存成功后只按既有边界清除文字；图片仍留在原输入框时明确提示用户手动移除，避免误以为已移走后重复发送。

## 验证

- 纯图片和图文草稿可保存；待办行显示图片数量，编辑文字不丢图片引用。
- 图片读取/格式/大小/持久化失败不清空草稿、不生成缺图待办；图片缺失时恢复失败且保留待办。
- 原生队列输入结构和完整图片恢复路径通过测试；运行 `npm run check` 与 `npm test`。原生窗口实际交互若受工具权限限制，单独标明未验收。
