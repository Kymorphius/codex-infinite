# Native sidebar session labels

- Status: shipped
- Owner: Codex Control Console
- Date: 2026-08-31
- Related ADRs: none

## Problem

Native Codex sidebar entries show a conversation title but do not expose the
current project name or the device that owns the conversation. Reusable task
titles therefore become ambiguous across many projects and machines. Embedding
those values into the persisted title would become stale after a project or
device is renamed.

## Goals

- Add a current-project tag to indexed native sidebar conversations.
- Add a location tag that reads `本地` for the local node and the configured
  device name for a remote node.
- Refresh both tags from normalized task metadata without rewriting titles.
- Preserve native sidebar ordering, expansion, pinning, navigation, and React
  ownership.
- Cover every bounded native thread recorded in the read-only state database,
  including threads older than the general task-list window.
- Treat explicit current project membership as authoritative over a rollout's
  original working directory when choosing the displayed project name.
- Keep labels stable while React reconciles native sidebar rows.

## Non-goals

- Creating the `现在`, `等待`, `本周`, or `待整理` attention views.
- Inferring or rewriting the `[动作类型] 对象` title format.
- Labeling conversations absent from both the task index and native state.
- Reimplementing native projects or moving native sidebar DOM nodes.

## User experience

An indexed conversation keeps its native title and gains two compact,
non-interactive tags: the latest project display name and either `本地` or the
remote device name. Tags update in place after the normalized task snapshot
changes. Missing or failed metadata leaves the native entry unchanged. Tags are
presentation-only and excluded from accessibility text so the native button
continues to own its accessible name. The two tags form a right-aligned group,
leaving the native title to use and truncate within the remaining row width.

## Contracts and data

The injection boundary receives a bounded array with only:

- `threadId`
- `projectLabel`
- `deviceLabel`

`projectLabel` is derived from explicit current project membership first, then
from `projectDisplayName`, and finally from the stable project key or bounded
working-directory basename. `deviceLabel` is `本地` for `local-codex`;
otherwise it is the normalized device name or `远端`. No state is persisted
and no project files, credentials, paths, prompts, or message bodies cross the
injection boundary.

## Design and ownership

- `src/native-sidebar-labels.mjs` owns bounded projection, refresh caching, and
  the isolated DOM-label injection source.
- `src/current-thread-projects.mjs` provides a bounded all-thread read from the
  same read-only native state database used for current membership overlays.
- `src/injector.mjs` and `src/native-owner-injector.mjs` install the isolated
  source and synchronize its latest snapshot through CDP in both the dedicated
  Control Console window and the primary Codex window.
- `src/main.mjs` wires the federated read-only task adapter into the label
  provider.
- The injected observer only decorates existing
  `data-app-action-sidebar-thread-id` elements. Labels are generated by CSS
  from bounded data attributes on the native title host, rather than inserted
  as React-owned children. The injection never reparents or reorders native
  elements.

## Security and privacy

The existing loopback and CDP boundaries are unchanged. The projection contains
only bounded display labels and UUID thread identifiers. The browser never
reads the filesystem or peer credentials, and the feature adds no mutation
route or network listener.

## Rollout and rollback

The feature is installed with the existing dedicated-wrapper and primary-owner
injectors. Removing the isolated source and provider wiring removes every
injected tag on the next page load. A version change disconnects the previous
observer and removes old tags before reinstalling.

## Acceptance criteria

- [x] Indexed native conversations show current project and location tags.
- [x] Local conversations display `本地`; remote conversations display their
  configured device name.
- [x] A changed project display name replaces the old tag without a title edit.
- [x] Native title text, ordering, expansion, pinning, and navigation remain
  native-owned.
- [x] Missing metadata adds no placeholder tag and causes no sidebar failure.
- [x] Injection snapshots are bounded and exclude paths, prompts, messages, and
  credentials.
- [x] `npm run check` and `npm test` pass without a structure-budget increase.
- [x] A moved conversation immediately shows its explicit current project,
  even when its working directory still belongs to the former project.
- [x] Native conversations older than the general 160-task index receive
  labels from the bounded read-only state projection.
- [x] Repeated native React reconciliation does not remove and recreate label
  child nodes or cause visible label flicker.
- [x] Project and device tags align as one group at the right edge of the
  native conversation row.

## Shipped deviations

None.

## Shipped evidence

- The live dedicated Codex sidebar exposed 22 native thread markers and three
  currently indexed visible entries received label strips immediately after the
  managed service restart.
- The active `mulitca` conversations displayed the current renamed project
  label `看板` and the location label `本地`; a `PAKeys` conversation displayed
  `PAKeys` and `本地`.
- A screenshot of the primary Codex sidebar exposed that the first shipped
  pass covered only the dedicated wrapper. The accepted implementation now
  installs the same bounded label source and snapshot through the primary-owner
  injector as well.
- The injected label nodes remained children of their existing native thread
  buttons; no native thread or project node was moved.
- Initial live layout placed the label strip after the fixed-height native row,
  which overlapped the following conversation. The shipped layout resolves the
  native title flex host and moves the strip into that single row. Frame-based
  resynchronization prevents continuous native mutations from starving the
  relocation. Live geometry measured the label bottom at 311px and the next row
  top at 318px with no overlap.
- Each tag now has a versioned 36px minimum width. Live geometry confirmed both
  `看板` and `本地` render at 36px with `scrollWidth === clientWidth`, so two
  Chinese characters remain fully visible before longer values are ellipsized.
- A later narrow-title regression showed that the label strip itself could
  shrink to 54–60px while its two 36px tags required 75px including the gap;
  the intact tags were therefore clipped by their parent. The strip now reserves
  a non-shrinking 75px minimum, leaving title truncation to absorb constrained
  width while guaranteeing both two-character labels remain visible.
- Local labels are projected immediately while federated peer metadata refreshes
  in the background, so an unavailable remote device cannot temporarily empty
  the local sidebar after a service restart.
- The current-state projection returned labels for all 424 native threads in
  the local read-only database, compared with the general task index's
  160-thread window.
- Moved-thread regression coverage confirms an explicit current project name
  wins even when directory-based display metadata still resolves to the former
  project.
- Label pills now use generated content on bounded host attributes. No label
  child is inserted into a React-owned conversation row, removing the
  remove-and-reinsert cycle that caused visible flicker.
- Syntax and structure checks passed for 233 and 253 files respectively with
  zero frozen debt. All 352 tests passed.
- Syntax and structure checks passed for 172 and 190 files respectively with
  zero frozen debt. All 245 tests passed.
