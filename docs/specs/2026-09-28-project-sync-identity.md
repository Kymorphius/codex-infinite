# 跨设备项目身份与副本关联

- Status: implementing
- Date: 2026-09-28
- Parent: 2026-09-26-git-project-sync.md, stage 2

## 行为

将已登记的两个项目副本关联为同一个共享项目。用户先完成现有 Git 预检，再单独点击「关联这两个副本」；不因名字、目录或 remote URL 相似而推断身份，不自动更新代码。每个设备保存自己目录与共享 UUID 的对应关系，换协调设备或重启后仍可读取。选择源项目时，页面优先展示同一共享项目的其他设备副本，但保留显式目标选择，不自动执行。

关联是可撤销的寻址信息，不替代 Git 状态、历史、任务活动检查或原生项目权限。用户可解除所选副本自己的关联，不删除项目、代码、会话或其他设备的关联。两个不同共享身份不能隐式合并，先解除误关联再重新预检。

## 一致性与持久化

- 每节点私有 wrapper home 中保存 versioned JSON，最多 5000 条映射；原子替换、排他写锁、限制输入大小，损坏时失败关闭，不能静默覆盖。崩溃遗留锁明确提示维护，不自动抢锁。
- 写入只接受原生已登记的规范目录，关联前重新检查洁净 Git 快照和任务状态。解除只更改元数据，允许有未提交改动，但仍核验登记目录及预期 UUID。
- 预检绑定两端当时的身份，执行关联或代码同步前再次比对。关联使用一次性预检凭据，按固定设备/路径顺序更新，节点写入以 expected project ID 做比较后替换；同一身份的重复请求可读回，不能覆盖不同身份。
- 这是两端分别持久化，不宣称跨设备原子事务。中途断网可能只完成一端，报告「关联未完整确认」，保留已写元数据；刷新后重新预检可沿用已有 UUID 完成另一端。禁止自动重试写入或自动回滚用户可能已经使用的身份。双方最后独立读回一致才显示成功。
- catalog 声明 identity capability。旧节点仍可原有代码同步，身份操作显示升级提示。浏览器写操作沿用 exact-origin，节点操作沿用签名、防重放、尺寸限制与 mutation 不重放规则。

## 本轮边界

这是阶段 2 的共享身份基础。新副本创建、未提交 checkpoint、环境准备仍待后续；创建必须通过实际桌面运行时完成项目登记和读回，不能直接用历史复制所产生的独立会话当作交接。会话/任务 owner、自动调度不在本轮实现中。

## 验收

验证持久化重启、三设备共享身份、不同项目冲突、并发比较写、损坏/锁、一次性凭据、两端版本变化、部分成功恢复、读回失败、不自动重试、旧节点；真实临时 Git 仓库中关联/解除不改变 HEAD、工作树或 Git 配置。页面验证已关联副本提示、手动目标确认、错误及刷新恢复。运行项目 check/test，实际页面验收并记录部署边界。
