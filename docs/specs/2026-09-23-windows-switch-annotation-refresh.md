# Windows 会话切换时的批注刷新范围

## 问题与目标

Windows 增强版切换会话时，批注观察器把侧边栏、顶部标签等无关 DOM 变化也当作批注上下文变化，随后读取轮次与布局。实机 A/B 显示批注导航会增加切换稳定时间。目标是在保留批注、轮次导航、滚动跟随和输出卡片定位的前提下，只对相关 DOM 变化重新读取批注上下文。

## 行为约束

- 会话正文、轮次标记、会话身份及输出卡片的挂载或卸载仍触发刷新；这些元素内部的子节点变化也触发刷新。
- 侧边栏和其它无关区域的子节点变化不触发批注刷新；即使其父节点包含会话正文，也不因父节点的后代匹配而误触发。
- 滚动、窗口尺寸变化、批注输入、服务端确认及展示状态切换保留原有刷新路径。
- 轮次轨道只给当前轮次写入 `aria-current=true`；其它轮次不写冗余的 `aria-current=false`。阅读位置切换仍立即响应。
- 轮次轨道按钮与轮次数组按同一顺序生成，绘制时按索引对应，避免每个按钮都重新遍历所有轮次。
- 不删除、隐藏或关闭任何增强功能，也不改变草稿或批注持久化格式。

## 验证

- 用隔离测试覆盖相关节点挂载、卸载、内部变化和无关侧边栏变化。
- 跑项目完整检查与测试，并在 Windows 已安装运行时读回注入版本、复测相同会话切换路径。
