# Hermes 看板：项目与执行目标

状态：已实现并在本机原生/Web 看板验证。

## 目标

在 Hermes 原生与 Web 看板中选择本机已有项目，明确卡片由 Hermes 新会话执行，或继续该项目中的已有 GPT 会话。显示设备、项目、实际工作目录、执行者和会话关系；打开对应会话并查看执行结果。保留原看板、任务、登录与各应用的数据所有权。

## 权威边界

Hermes 看板持有任务状态和执行目标快照。Hermes 新任务使用原 dispatcher 和工作树流程；GPT 任务只能交给当前本机原生 GPT owner，沿用原会话模型与审批。共享项目从原目录实时读取，不写入或复制到 Hermes 项目库。当前只支持本机；不提供未经验证的远端执行或 GPT 新建会话选项。

后端使用显式本机配置的固定 JSON 子进程适配器，HTTP/renderer 请求不能指定命令、端口、程序或环境变量。适配器验证项目与会话所属关系、设备、实际 cwd、草稿、原运行状态。只读查询不得触发执行。

## 执行

新增可选 execution_target 字段，兼容原任务。新卡片选择项目与执行方式；GPT 方式必须选择同项目未归档会话，工作目录由原会话确定，不允许覆盖。Hermes 方式选择目录/worktree并建立新任务会话。创建事务原子保存任务与目标，禁止创建后临时换执行者。

GPT worker 使用原任务 claim/run、heartbeat、停止和结果记录。发送前持久化一次性提交记录，任何发送结果不明、worker 崩溃或重复调度均不自动重复提交，不回退 Hermes。回复按原执行轮次匹配，后续手动轮次不能冒充本次结果。停止仅作用于绑定的原轮次。GPT 的模型/技能/goal/triage 自动改写选项不能悄悄覆盖 owner。
