# Native ChatGPT conversation project move

- Status: implemented
- Owner: Codex Control Console
- Date: 2026-09-01
- Related ADRs: none

## Problem

The native sidebar returns ordinary ChatGPT conversations and cloud Work in one
`chatGptSource.chatTargets` collection. The supported Codex sidebar mutation
contract rejects ChatGPT conversation keys, while the native conversation menu
contains the authenticated `move-chatgpt-conversation-to-project:<project-id>`
actions required to assign an ordinary chat to a ChatGPT project. The popup
itself is not reliably exposed as a DOM or macOS accessibility menu in this
desktop build, so visible automation cannot safely select it.

## Goals

- Move one ordinary ChatGPT conversation to one exact ChatGPT project by
  invoking the action already generated by the native conversation menu.
- Resolve both conversation and project by stable IDs, never by localized text.
- Verify the native normalized state reports the requested `projectId` before
  returning success.
- Fail closed for cloud Work, Codex tasks, malformed IDs, missing rows, missing
  menu actions, application-version drift, ambiguous state, or timeout.
- Keep moves serialized and idempotent.
- Preserve credentials inside the native renderer and CDP boundary.

## Non-goals

- Calling, documenting, or reverse-engineering a private ChatGPT HTTP endpoint.
- Providing a public or LAN-reachable mutation route.
- Moving cloud Work, Codex tasks, scheduled items, or archived conversations.
- Creating, deleting, renaming, merging, or deduplicating ChatGPT projects.
- Choosing a project by display name.
- Automatically classifying conversations in this adapter.

## Design

`src/chatgpt-project-move-contract.mjs` owns pure ID validation and normalized
request policy. Conversation IDs must be UUID-shaped and ChatGPT project IDs
must use the observed `g-p-` identifier form. The contract accepts only a
normalized source of `chatgpt`, requires an unassigned or already-targeted
conversation, and explicitly rejects `codex`/`tpp` cloud Work.

`src/native-chatgpt-project-adapter.mjs` is the CDP infrastructure adapter. It
connects only to the configured loopback desktop target and evaluates one
bounded renderer expression. The expression:

1. checks project conversation rows for an already-targeted exact conversation
   ID and exact `projectId`;
2. otherwise finds the exact native recent-conversation list item by
   `data-sidebar-chatgpt-conversation-key`;
3. reads the closest React-owned native conversation state and confirms the
   exact conversation is `source=chatgpt` with `projectId=null` or the requested
   project ID;
4. obtains the existing native `getMenuItems` function from the exact row;
5. finds the project submenu by the stable
   `move-chatgpt-conversation-to-project` action ID;
6. selects the exact child action whose ID ends with the requested project ID;
7. invokes and awaits only that child action's existing `onSelect` callback; and
8. polls both recent and project rows until the exact conversation reports the
   requested `projectId`.

An older conversation that exists in normalized recent state but has no native
row is not synthesized or mutated into view. It fails closed until the native
sidebar has rendered the row.

The adapter never exports cookies, callback source, menu contents, or renderer
state. A successful response contains only normalized IDs and `applied` or
`alreadyApplied`. All failures are bounded user-safe errors. The connection is
always closed.

The OpenAI public Projects API represents API organization projects and does
not provide this ChatGPT sidebar operation. This adapter is therefore explicitly
version-sensitive and must fail closed when the native menu contract changes.

## Safety invariants

- The CDP origin remains literal loopback.
- No credential material or private endpoint enters logs or responses.
- `source=codex` or `conversation_origin=tpp` is never movable.
- Project display names are never authorization or identity.
- No fallback private request is attempted when the native callback is absent.
- Only one move is active per adapter instance.
- Success requires a post-action native `projectId` observation.

## Acceptance criteria

- [x] Malformed conversation and project IDs are rejected before CDP access.
- [x] Cloud Work and non-ChatGPT sources are rejected inside the renderer.
- [x] An already-targeted conversation returns idempotent success without
  invoking `onSelect`.
- [x] The exact native move action is invoked for an unassigned ordinary chat.
- [x] Missing rows, menu actions, project actions, and verification timeout fail
  closed.
- [x] Concurrent moves are serialized.
- [x] The CDP connection closes on success and failure.
- [x] Focused tests cover validation, idempotence, success, rejection, timeout,
  and connection cleanup.
- [x] `npm run check` and `npm test` pass.
- [x] One live ordinary-chat sample updates to the exact target project while
  all cloud Work remains unchanged.

## Rollback

Remove the adapter and its contract. No persistent renderer injection or data
migration is installed. Conversations already moved remain in their native
ChatGPT projects and can be moved again through the native product.
