# 伴生 Claude 会话：实时镜像 + 按需交互

## 背景

伴生 Claude 会话（Codex 会话选用 Router 的 Claude 模型后，Router 维护的那份 Claude CLI 会话）以前按
「轮流占用」工作：在终端里打开它就常驻一个交互式 `claude --resume`，Router 看到会话被占用就拒绝
Codex 这一轮（409 `CLAUDE_SESSION_OPEN`）；Codex 一轮进行中，终端只读。用户要求两边同时可看、都能发。

两个 Claude 进程同时写同一会话会分叉（已实测），所以不同时运行两个进程；改为「没有人常驻占着会话」。

## 行为

终端里打开伴生会话，默认进入**镜像模式**：

- 实时显示这个 Claude 会话的记录：Codex 发来的消息（只取 Router 包装里最后的用户消息，标注
  「Codex」）、终端里发的消息（标注「你」）、Claude 的回复正文与工具调用摘要。思考过程、工具输出、
  元数据不显示。Codex 一轮进行中也随写随刷新。
- 镜像模式下在输入框发送，每条消息用一个一次性进程执行
  （`claude -p --resume <会话> --permission-mode bypassPermissions`，跑完退出），结果出现在镜像里。
  模型与推理强度沿用 Claude 默认设置（伴生会话的模型选择仍属于 Router/Codex）。
- **交互模式**：会话栏按钮「交互模式」启动完整交互式 `claude --resume`（原有行为，含斜杠命令）。
  此期间 Codex 发送会被 Router 以 `CLAUDE_SESSION_OPEN` 提示，与以前一致。进程退出后回到镜像模式。

## 同一时刻只执行一轮

- 占用判断沿用 Claude 自己的登记表（`~/.claude/sessions/<pid>.json`）。一次性进程登记为
  `entrypoint: "sdk-cli"`。
- Router：会话只被一次性进程占用时**等待其结束**再续接（最长 15 分钟，客户端断开即放弃），
  被交互式进程占用时仍返回 `CLAUDE_SESSION_OPEN`。
- 控制台：发送前同样等待一次性进程（通常是 Codex 这一轮）结束；有交互式进程占用则拒绝并说明。
  同一会话的控制台发送串行执行。
- 两边几乎同时开始时仍有极小的竞争窗口（各自检查登记表到新进程登记之间）；不引入跨进程锁文件，
  因为 Router 的伴生目录对外只公开 `session.json`。

## Codex 侧可见性

Codex 窗口只显示 Codex 自己的对话；终端里说的话不回写 Codex 历史，但 Claude 会话本身包含它们，
下一轮 Codex 续接时 Claude 知道。

## 边界

- 只读取该会话（及其续接链的当前记录）的 transcript，不读 Claude 设置或凭证。
- 镜像接口为 POST（与其他终端会话接口一致，精确来源校验），单次最多返回 400 条、首屏只读取末尾 2 MB。
- 非伴生的 Claude 终端会话行为不变。

## 验收

- 镜像解析：Codex 包装、终端消息、回复、工具摘要、跳过项；游标增量读取。
- 发送：等待一次性占用者、拒绝交互式占用者、同会话串行。
- Router：一次性占用者等待后续接；交互式占用者仍 409。
- 实际窗口：终端镜像显示 Codex 轮次；终端发送后 Codex 下一轮能接上；交互模式往返。
