# 会话模型批量替换

## 目标

在“项目与会话”提供统一入口，按已记录的旧模型选出会话，选择所属节点实际支持的新模型，一次提交替换。例如将 `gpt-5.6-sol` 换为 `gpt-6-sol`。

## 行为

- 用户选择旧模型和新模型后，先显示命中总数、可处理数、不可处理数及设备范围。范围是当前会话索引已经收录的记录，每个节点沿用索引的扫描上限。只处理当前仍连接、标识有效且所属节点模型目录明确支持目标模型的会话。
- 变更逐条交给会话所属节点的原生设置服务；即使某条失败也继续其余会话。每条请求携带预期旧模型，节点在应用前重新检查，避免误改已被其他窗口调整的会话。
- 模型切换沿用单条会话设置的推理强度和速度兼容规则；原值受支持时保留，否则使用新模型默认值。运行中的轮次不改变，仅从下一轮生效。
- 执行结果明确区分已接受、失败和跳过。不会改动模型未知、离线或目标模型不受支持的会话。会话索引仍为只读。

## 验证

- 检查本机和远端的设置路由、精确来源校验、预期模型冲突。
- 检查批量预览只选中准确的源模型和受支持节点，以及逐条失败后的结果汇总。
- 运行项目的 `npm run check` 和 `npm test`。
