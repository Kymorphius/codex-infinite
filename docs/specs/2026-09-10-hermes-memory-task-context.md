# Hermes 记忆与任务上下文接入原生 GPT

## 目标

在已有本机共享会话和看板执行链路上，让原生 GPT 按需读取 Hermes 的长期记忆、
检索 Hermes 过往公开对话，并通过 Hermes 正式记忆入口保存用户授权的长期事实。
看板派发需传递任务背景、依赖成果和备注；执行结果继续按原始回合回收到原卡片。

## 接口和责任

- Hermes 项目提供独立 stdio MCP `hermes-context`，在进程启动时固定 `HERMES_HOME`。
  客户端不能传文件路径、切换 profile 或执行任意代码。无监听端口。
- `hermes_memory_read`：读取当前 profile 的原生记忆快照，支持字面检索和分页。
  沿用原生注入内容检查，返回来源、开关、容量和明确的分页状态。
- `hermes_memory_update`：调用原生 `load_on_disk_store` 与 `memory_tool` 的单项
  add/replace/remove，不直接改写文件。保留容量、并发重读、内容检测和
  `memory.write_approval` 规则；区分已保存、待审批和失败。不得把完成日志整段写成记忆。
- `hermes_session_search`：复用原生会话检索，当前 profile 数据库只读打开；
  仅输出 user/assistant 公开文字，过滤工具、系统字段和压缩上下文。
  搜索及按消息锚点翻看均有界；不跨 profile 自动兜底。
- `hermes_task_context`：按明确的看板 slug 与 task ID，只读获取原生 worker
  context，包含依赖结果、先前执行与备注。结果按修订分页，超长必须明确告知。

这些结果是来源资料，不是新的执行权限或系统指令。保存记忆须遵守当前用户的
授权和上层指令；工具描述不能授予自动写入权限。不得写入 Codex 私有记忆目录。
Hermes 原生 provider 插件、技能学习和跨设备配置不在本阶段声称覆盖的范围内。

## 看板连接

外部 GPT worker 改用原生 `build_worker_context` 形成有界派发内容，附明确的
看板/task 标识及进一步获取上下文、记忆的工具指引。上下文超长显示截断并要求
通过工具补读。保留现有一次发送、原回合绑定、未知结果不重发及人工审核路径。
GPT 会话不会获得可随意完成其他看板任务的写入工具。

## 部署

仅在本机增强版原生前端的实际配置目录添加这一 stdio MCP；显式设置当前 Hermes
profile 路径，保留已有插件、账户、模型和审批配置。沿用原生 MCP 刷新流程，
仅刷新空闲验证会话，不能因工具重载中断其他任务。无需重建 Hermes 聊天界面。

重启验证发现旧 `prepareWrapperCodexHome` 每次启动都会以源配置覆盖增强版配置，
使新增 MCP 和原生插件刷新结果丢失。修正为：源配置仅用于首次初始化；已有配置
归增强版前端所有，启动只继续清理包装层管理的根级上下文容量键，不同步覆盖
其余配置。不修改源配置，不复制其他机器配置。必须测试重复初始化后本地 MCP、
插件来源和模型选择保留。

进程中断可能使原转录只留下 task_started。共享历史在该标记超过 60 秒且原生
所属会话明确空闲时，重新读取确认转录未变化，然后只在返回结果中清理运行标记、
标注 interruptedTurnId。原生状态未知、仍在执行或转录发生变化时保持保守；
不编辑原始会话记录，也不自动重发此前卡片。

## 验收

1. 隔离 fixture 覆盖禁用状态、profile 隔离、只读检索、内容过滤、分页、记忆
   容量与并发更新、审批待处理、不覆盖未知条目、非法看板路径和缺失任务。
2. MCP 协议测试实际启动子进程，验证发现与调用，错误不被报告成成功。
3. 从 Hermes 的已有共享会话实际调用记忆读取和历史检索；测试记忆写入使用
   隔离 profile，验证经正式工具保存后下一次读取可见，不污染用户真实记忆。
4. 实际看板任务取得备注/依赖上下文，回复被原卡片按正确回合收回。
5. Hermes 按正式测试脚本运行针对性测试；Control Console 检查与全量测试通过；
   实际 UI 结果与工具回执分别核对后提交本次文件。
