# 领取任务与会话待办身份一致性

## 问题与目标

用户领取 jev 分类任务后，当前会话待办却显示其他会话的两条任务。保存记录中任务 ID 和内容仍各自独立。源码确认：领取优先读取第一个已挂载 composer，而同步读取最后一个；同步跨异步调用发布无会话标记的数组；切换会话未清理已领取任务缓存。

目标：点击领取、保存分配、展示待办、手动恢复始终绑定同一任务 ID 和会话 ID，导航及迟到响应不得把其他会话的任务带入当前会话。

## 设计与边界

- 领取、待办和同步统一使用 `readNativeComposerThreadId`；保持现有最后挂载 composer 优先、侧边栏选中项兜底的规则。
- 同步发布 `{ threadId, items }` 快照。接收端拒绝未标记或非当前会话快照；渲染时再次按所属会话隔离。
- 会话改变或退出时清空界面缓存，不删除持久化任务。监听 composer 身份属性和原生选中状态，切换时立即移除旧行。
- 恢复操作校验捕获的会话、任务 ID 和内容仍与当前快照一致；异步结果只刷新原操作会话。完成标记按综合清单的精确任务和会话归属写回，不依赖当前打开哪个清单。
- 领取按钮捕获明确的任务与领取目标；清单刷新、切换后遗留的回调不得重新指派或改写其他任务。
- 更新注入版本以替换驻留旧脚本。领取仍只创建暂停待办，不自动发送；不改用户已有任务归属，不推送或发布。
- 版本升级时重建领取按钮，不能复用仍闭包到旧会话解析器的点击监听器。原生 RPC 传输从接近文件预算上限的待办模块提取到 `native-held-queue-bridge.mjs`，保持方法白名单、超时和响应关联规则不变。

## 验证

- 同时挂载两个 composer 时领取与同步会话一致。
- 点击指定任务后持久化及投影保持相同 ID、文本和目标会话；顺序变化不影响对应关系。
- A 切换 B 后、下一次同步前不显示 A 任务；A 的迟到快照不覆盖 B。
- 老版本无归属数组被拒绝；同内容快照不重复重建面板。
- 旧版驻留领取按钮升级后被替换，点击必须使用新版会话规则，页面只有一个领取按钮。
- 旧行恢复不发送，已启动的 A 恢复完成不改写 B 的显示；精确完成 A 任务不依赖当前打开的清单。
- 运行针对性回归、`npm run check` 与 `npm test`。真实界面验收仅使用允许的 UI 接口；受限时明确记录未验证范围。
