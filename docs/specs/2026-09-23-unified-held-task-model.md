# 直存待办与领取任务统一模型

## 用户目标

“存待办”和从“领任务”领取的内容都是任务。两者应只有一条权威任务记录：`ccc:general-inbox:v1` 中的同一任务 ID、正文、附件引用与归属状态。`assignedThreadId` 存在时显示在会话待办，退回时变为未指派，恢复发送后标记完成；退回后可用同一 ID 再领取。

## 数据与所有权

- 综合清单为任务权威源。直存新待办创建已指派的综合清单任务，不再创建独立的 `origin=draft` 待办记录。综合清单“添加任务”也支持粘贴图片；两条入口写入相同的任务载荷。
- 消息正文与本机图片引用保留在任务的有界 `input` 载荷中；图片字节仍由现有本机 IndexedDB 适配器保管。清单列表以任务文字/摘要呈现，不读取图片字节。
- 旧版直存待办通过保留原 UUID 的幂等迁移转换成综合清单任务；确认清单已持久化并发布权威快照后才移除旧记录。迁移失败或附件格式不支持时保留旧内容并显式提示，不删数据。
- 原生排队暂停项是未提交的原生队列输入，暂不冒充综合清单任务；用户从这些项恢复仍走原生队列桥接。

## 流转安全

- 直存先捕获并持久化附件，再将任务动作安全写入本地待同步清单。只有本地动作保存成功才清空输入框；服务端失败时保留可重试动作和附件。
- 已指派任务“退回”仅清空 `assignedThreadId`，保留 ID、文字与附件引用；原有会话校验、文本身份校验、回执确认继续生效。
- 恢复发送使用任务的 `input`；原生队列确认接收后，任务才标记完成。图片引用在任务仍可能重试时不得清理。
- 注入的清单界面每次重建都必须重新接收综合清单权威快照，即使存储内容未变化；入队后写入完成动作需检查本地持久化结果并唤醒同步，不能在完成动作缺失时静默报告成功。
- 对无法安全表达为有界任务载荷的内容失败关闭，不能静默丢图、截断正文或回退为第二套权威任务。

## 验证

- 契约测试覆盖正文、图片引用、无文本图片待办、长度/数量/引用格式拒绝；存储测试覆盖同 ID 领取/退回/完成、编辑不丢附件与幂等回执。界面测试覆盖“添加任务”粘贴 PNG/JPEG/GIF/WebP 图片，拒绝不支持的图片并保留未提交输入。
- 注入行为测试覆盖直存、待同步投影、旧记录迁移、恢复发送与失败保留。
- 运行态验证版本、真实控件与草稿；不使用用户现有任务做破坏性回归。`npm run check`、`npm test` 必须通过。
