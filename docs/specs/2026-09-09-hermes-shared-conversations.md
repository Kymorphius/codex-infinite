# Hermes 与 GPT 共用会话

状态：本机共享项目与文本会话已实现，并通过双端实机验收。

## 用户目标

GPT 与 Personal Panel 内的 Hermes 原生桌面界面都能打开、继续同一条会话，始终读取同一份历史；无需导入或持续复制。替换此前的历史附件选择器，不另建聊天面板。

## 权威与身份

现有 GPT 会话继续由原设备的原生 Codex 运行时执行和持久化。Hermes 界面仅作为这条会话的另一个客户端。Hermes 自有会话仍由 Hermes 执行。不得把同一历史交给两个引擎分别写入，不直接修改任一会话数据库或 transcript。

界面投影采用有来源命名空间的稳定标识，并在边界还原设备与原始会话标识。项目、标题、消息都是实时读取的投影，不生成 Hermes 导入记录。缓存仅用于显示，不能成为恢复或发送依据。

## 连接层适配

Personal Panel 现有 Hermes 公共桌面 API relay 作为适配边界。对项目和会话查询合并 GPT 来源；对选中的 GPT 会话将历史、状态、发送与取消转交原生 owner 接口。其余 Hermes 请求保持原连接语义。接口不支持的操作明确返回不可用，禁止落回 Hermes 创建同名新会话。

网络仅允许 loopback；连接凭据由主进程持有且不得写入日志或源码；renderer 权限继续限定当前可信主 frame。发送必须校验来源身份、会话存在、草稿版本、执行状态与重复请求。未知结果不得自动重发。断线保留输入，显示错误，不切换到其他执行者。

## 验收

- 原生项目列表内选择 GPT 项目和会话，消息区加载其实际历史，可读取更早消息，无静默截断。
- 在 Hermes 输入独特无副作用的测试消息，GPT 原会话中出现该用户消息及回复，各只出现一次。
- 在 GPT 同一会话继续，Hermes 展示新增消息，原始会话 ID 不变；两边无导入会话。
- 正在运行、已有草稿、切换会话后迟到响应、断线和超时均不串会话或覆盖草稿。
- 原有 Hermes 会话正常打开和续聊；后台管理入口独立可用。
- 自动检查、适当行为测试和实际桌面交互均通过后，才标记完成。
