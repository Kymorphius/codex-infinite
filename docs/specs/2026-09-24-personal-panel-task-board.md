# Personal Panel 原生任务接入控制台任务看板

## 权威与身份

Personal Panel 的 Anytype 原生任务是该来源的唯一权威。控制台现有综合任务清单和发送调度仍各自保持现有权威；看板只并列投影，不以同名或文本相似自动合并、复制或迁移。跨系统身份为 `{accountId, spaceId, taskId}`，不能仅凭标题配对。

## 边界与动线

- 控制台仅通过 Personal Panel 提供的受限单次 CLI 桥接访问 `task.list`、`task.update`、`task.complete`；不得调用高权限维护 socket、读取 Anytype 数据库或开放新网络监听。桥接路径由本机配置指定，不把另一设备路径写死在共享代码中。
- 看板展示原生任务名、原始状态、规划日期与分区。未知历史状态进入“待核对”，不推断为待办或完成。读失败显示错误，不显示伪造的空列表；桥接未配置时不影响原有看板。
- 可写且版本明确的任务可选择开始、暂停、回到待办或完成；请求带完整 owner、taskId 和读取时 revision。完成操作单独调用 `task.complete`，不伪装为普通状态更新。只允许精确来源同源页面变更。
- 写后必须重新从原生桥接读回。断线、超时或回执不确定时不自动重试，保留错误并要求刷新核对，避免重复写入。导入/旧对象和未知状态只读。
- 适配器读操作最长等待 60 秒；写操作允许原生维护路径超过 180 秒，等待上限 210 秒。页面刷新不应再发起同一写入。
- 第一阶段不在两个权威源间复制任务，也不从 Anytype 任务自动发送 Codex 消息。后续若需显式关联，必须保存双方稳定 ID、来源和确认状态。

## 验证

契约、来源校验、失败关闭、看板分区与动作测试；`npm run check`、`npm test`。原生 Anytype 和安装版界面需另做真实读回验收。
