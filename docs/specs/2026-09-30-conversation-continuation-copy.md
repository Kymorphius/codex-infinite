# 跨设备复制会话以继续工作

## 用户行为

已登记且同一共享项目身份、同分支/HEAD 的两个洁净副本间，用户选择源项目内一个已结束的主会话和目标项目，预检后明确确认复制。目标获得独立原生会话 ID，可读原历史、工作目录指向目标项目。源历史保留。页面直接说明这是继续工作的副本，尚不转移运行进程或源会话写权限，不自动发送提示/开始任务。

首版拒绝 active/unknown 状态、subagent、fork 或记录中外部会话依赖；复杂会话图后续按完整闭包迁移，不能默默丢失依赖。用户可选交接说明，作为私有操作记录返回而非自动消息。

## 合同与安全

- 浏览器入口使用 exact-origin POST，设备入口使用现有签名、限额、防重放 SSH-to-loopback；导出内容不返回浏览器、不进入 URL/命令行/日志。
- 源只读已登记根目录内会话：ID 与 session_meta 精确匹配，sourceFile 必须是真实普通文件，规范路径在配置 sessionRoot/archivedSessionRoot 内，最大 8 MiB。前后严格原生状态检查和完整 SHA-256 防止读取时源变化。
- 两端项目须已经显式关联同一 sharedProjectId。预检与执行都复核代码快照与源历史哈希。短期一次性 token；原生导入失败/超时不自动重试写入。
- 目标执行绑定持久记录中的项目快照；调用方不能用更新后的版本覆盖旧预检。仅预检不授予恢复写入权限，执行授权持久化后才能恢复。过期且未授权的预检不占待处理配额，授权后未完成的操作带 resumeEligible 标记，可在刷新后重新发现。
- 协调器仅在尚未发送目标执行请求时返回 applyStarted:false。页面只据此解除未开始操作的恢复状态；网络超时及已发送请求的失败保留原操作，禁止自动重发。
- 项目同步页的会话复制入口默认隐藏，仅在已加载服务确认能提供新页面后显示；等待重载的设备继续使用原项目同步页面。
- 目标只写配置本机会话目录及私有收据；从校验包重建临时源，复用 cloneNativeProject(indexOnly) 的历史 ID 重写/校验/持久 UUID。只绑定到现有目标项目，通过 app-server project/list 路径匹配解析 projectId，不导入新项目、不直接写 native global-state/原生数据库。
- 完成须独立 thread/read 校验新 ID、rollout 路径及目标 cwd；thread/turns/list 至少读到历史；thread metadata 项目归属也读回验证。无自动 turn/start。未知结果保留副本和 operationId，通过显式恢复重新核对同一 receipt 的 UUID，不生成新会话或重复历史。
- 历史只读索引、设备凭据独立和源端不被写入保持原有不变量。操作记录状态不是单 owner 转移。

## 模块边界

项目同步 runtime 挂接独立 continuation 适配器；协调服务不依赖 filesystem/CDP。源包验证、目标原生导入、协调与 UI 各自独立。src/main.mjs 不增加产品逻辑。

## 验收

真实文件哈希、ID 重写与原生 read/turns/metadata 合同；active/source-changed/项目未关联/版本不一致/路径逃逸/符号链接/超限/外部图依赖均拒绝；签名 origin、防重放、写入无重试；持久恢复只处理同一 UUID。npm run check、npm test。实机使用专用验收会话；不复制用户真实历史、不开启真实任务。功能加载状态与原生实机读回分别报告。
