# 会话待办退回后即时同步领任务

## 问题

已指派任务从会话待办点击“退回”后，操作先写入本地待同步清单；后台默认每 1200 毫秒轮询，且清单同步位于一轮增强注入与批注同步之后。会话待办行与“领任务”计数均等待清单落盘后的权威快照，因此可能延迟数秒。

## 行为与边界

- 退回操作通过现有清单桥接校验任务身份、所属会话和原文。本地待同步操作成功保存后，发出不包含任务正文的即时同步信号。
- 后台复用现有清单同步与幂等回执，不新增第二份任务状态。若常规同步正在进行，记录唤醒请求并在该轮结束后立即处理；同一时间至多执行一轮清单同步。
- 保存失败不发信号；CDP 断开或清单写入失败时保留原有待重试操作和错误提示，不提前移除待办或虚增“领任务”计数。
- 保留 1200 毫秒轮询作为恢复机制，不扩大到其他清单编辑动作，也不改全局轮询频率。

## 验证

- 测试信号仅在退回草稿保存成功后发出；忙碌期间多次信号合并，完成后及时处理，失败仍由常规轮询恢复。
- `npm run check` 和 `npm test` 通过；本机运行态读取增强版本、队列/领任务控件与草稿状态。真实退回耗时须在有可安全操作的已指派测试任务时单独验收，不改动用户现有任务作为测试数据。

## 本机验收

- 运行态版本为 `2026-09-23.return-wake1`，即时 CDP 绑定为函数；原会话和空草稿保持，当前清单没有待同步操作，控件仍显示“待办 0 / 领任务 32”。
- 对空待同步清单发送无任务数据的唤醒信号，约 210 毫秒后观察到清单 `packet()` 读取。该值只衡量唤醒到开始处理，不代表真实任务退回的持久化总耗时。
