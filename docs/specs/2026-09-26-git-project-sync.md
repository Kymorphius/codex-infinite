# Git 项目跨设备同步

- Status: implementing a bounded first release; task handoff remains proposed
- Date: 2026-09-26

## 目的与现状

用户需要按设备负载切换项目执行位置。现有 Windows 项目复制和同平台多根克隆产生独立副本，不提供对已有项目反复更新的闭环。本次先交付手动选择源设备/项目及目标设备/已有项目、预检、Git 快进同步、结果读回。项目和会话仍由各设备原生运行时管理。

## 首版范围

- 普通单根 Git 仓库之间传输已提交 HEAD 与其历史，只支持同分支且目标是源祖先的快进更新；相同 HEAD 返回无需同步。
- 用户显式选择两端目录；不按项目名、路径尾部或带凭据的 remote URL 自动认定项目身份。
- 只允许当前设备已登记的原生 Codex 项目根目录；拒绝子目录、符号链接根、worktree、裸仓库、submodule、LFS、未提交/未跟踪改动、冲突与进行中的任务。
- 预检绑定源和目标的分支与提交，凭据短时有效且一次性使用。执行前重新读取两端状态，任何变化都要求重做预检。
- 协调端最多 4 个在途预检及 32 个待确认预检；目标端最多 8 个准备中/待确认临时包，每包不超过 24 MiB。源变化或浏览器放弃后的目标包最长保留至 10 分钟凭据到期，在下一次目录读取、预检或执行时清理。进程重启使所有凭据失效；首次版本的私有系统临时目录可能留有崩溃后的包，不宣称具备持久操作恢复。
- 使用 Git bundle 传递 Git 对象；不复制 .git/config、hooks、凭据、ignored 文件、设备配置、会话索引、任务队列、依赖和运行数据。Git 已跟踪内容遵循版本记录；明确阻断常见凭据文件，说明过往历史仍属于所选仓库。
- 目标暂存包在私有临时目录校验，拒绝无共同历史、分叉和目标领先；只用 fast-forward 更新，不 reset、不 stash、不自动提交/合并、不强推。
- 成功以目标 HEAD、分支和洁净工作树读回为准。传输/执行结果不确定时不能自动重放写入，不宣称成功，用户刷新/重新预检即可核对。
- 新目录创建、未提交改动迁移、多根/worktree、LFS、submodule、并行任务分支汇合、会话/进程交接、自动负载调度暂不在本次交付范围。

## 结构与接口

- 本地 Git adapter 隔离文件系统与 Git 进程；领域协调服务只处理标准项目选择、快照和预检凭据。
- 专用 SSH adapter 使用现有认证的节点动作通道；双方运行本版本才能参与。浏览器仅见选择、版本和摘要，不见 bundle 或凭据。
- GET /api/project-sync/catalog 返回每台设备的可选项目及读取状态；失败节点保留明确不可用状态。
- POST /api/project-sync/preflight {source:{deviceId,path},target:{deviceId,path}} 返回 token、源/目标快照与更新摘要。
- POST /api/project-sync/execute {token} 消费预检并返回 verified、目标快照。
- /api/node/project-sync/{catalog,inspect,export,prepare,apply} 均为签名 POST；只有 apply 更新目标。校验签名、请求限额与 replay protection。
- 独立项目同步页面从项目管理入口进入，展示源/目标方向、分支、提交、阻断原因、预检/执行阶段。更改选择立即丢弃预检，不自动重试同步。

## 后续完整产品

用户已明确三种使用方式都需要，并要求从容易的开始：代码同步、项目/会话/任务交接、多设备并行分担。顺序如下，每一阶段单独验收。

1. **代码往返**（本次）：选择已有副本，预检、快进、读回；不丢两端本机状态。
2. **项目连续性**：持久共享项目 ID 与设备 checkout 映射、新设备创建副本、未提交 checkpoint、依赖和运行环境准备。不能仅按同名项目关联。
3. **会话与任务交接**：复用现有历史导入/子任务图保真能力；封存源任务、传递上下文和待办、验证目标可读历史，再通过原生能力完成单 owner 切换。需要持久 operation/receipt 和故障恢复，不能以创建新会话 ID 冒充原任务迁移。
4. **均衡运行**：显示可用设备与实时运行任务、给出目标建议；不同任务用独立分支/checkout 并行，结果显式汇合。同一任务只有一个执行 owner，不把整个项目限制为只能在一台设备运行。

阶段 2–4 尚未实现。项目代码同步不能被表述成正在运行的进程或会话已经迁移。

## 验收

真实临时 Git 仓库验证往返快进、相同提交、无关历史、分叉、脏树、未跟踪文件、过期预检、源/目标变化、重复执行；确认目标本机 Git 配置与 ignored 文件不变。测试未知目录、符号链接、worktree、活动任务和凭据文件拒绝。HTTP 验证 exact origin、签名/防重放、无 bundle 浏览器泄漏；UI 验证方向、变更选择失效和失败可见。运行 npm run check 与 npm test，并在实际页面走完预检、同步、读回流程；跨物理设备验证须单独记录，不能以本机两仓库代替。
