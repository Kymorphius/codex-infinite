# Jev 六维融合路由

## 问题

现有 Jev 只对八档作一次选择。低置信度时，Router 回到固定兜底档位，增强版原生模式则继续采用低置信度的选择；两条路径会给同一任务不同的模型。用户希望吸收 AutoRoute 的复杂度、范围、推理、风险、上下文和迭代六维判断，同时保留 Jev 的语义能力和自己保存的八档模型/强度映射。

## 行为

- 一次 Jev `run` 请求同时返回八档选择与六个 0–5 的维度评分；不为每个维度分别发请求。仅传当前轮次的有界任务文本，不传会话历史或凭证。
- 高置信度且没有明确高风险冲突时，以 Jev 八档选择为主。低置信度、缺失八档选择或明确高风险冲突时，用六维加权评分决定档位；六维数据不完整或不可靠时沿用用户配置的兜底档位。
- 分档完成后才读取对应的用户映射；六维逻辑不硬编码模型或推理强度，不改已有配置格式。确认式续聊仍继承上一轮；低置信度的下一轮不能低于上一轮档位。
- 返回选择来源与六维摘要，保留原始 Jev 置信度，不能把六维评分误称为模型质量或成功概率。失败、不支持 `run` 的旧 Jev 以及超时均安全退回原有兜底路径。
- Router 和增强版原生模式使用相同规格、分档算法和测试向量。配置关闭时不调用 Jev，也不做六维判断。

## 验收

1. 同一组模拟 Jev 响应在 Router、增强版得到相同档位；高置信度、低置信度、高风险冲突、缺项、错误和超时各有测试。
2. 保存的八档映射及传输模式原样保留；分档后的模型和强度来自选中档位，不从 AutoRoute 固定偏好中挑选。
3. 定向测试、仓库检查和全量测试通过；只在 Router 无活动请求时重启常驻服务，并验证增强版真实界面载入新版本。

## 边界

参考 [AutoRoute](https://github.com/you-want/AutoRoute) 的六维分析思想，不安装它的 Skill、不调用它的 `codex queue` 或独立会话启动器，也不自动发起逐模型可用性探测。模型目录仍由现有 Router 管理。实际准确率改进需要后续以真实任务 A/B 评估，单元测试不能证明这一点。
