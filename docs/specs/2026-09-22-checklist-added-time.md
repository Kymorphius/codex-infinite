# 任务清单加入时间

## 行为

- 项目任务清单、综合任务清单和领取列表默认按最初加入时间从早到晚展示；未指派任务在上、会话待办在下的现有分区保留。下方会话待办合并后按时间排序。
- 每行显示静态本地日期和时间，悬浮可查看含秒的完整时间；同一时间保持原有顺序。时间未知的旧记录置于该分区末尾，彼此保持原顺序。
- 编辑、完成、领取、改派、退回不改变加入时间。此视图排序不重写存储数组，也不影响会话待办的手动排序。
- 不增加轮询、MutationObserver 或相对时间刷新定时器；未变化的服务端确认不重建列表。

## 数据约定与兼容

- 清单项新增 `createdAt`（ISO 时间或 null）及 `createdAtEstimated`（boolean）。新任务在点击添加时生成时间，随待保存草稿保留；缺少客户端时间的新建请求由存储端记录当前时间。
- 已有记录的时间由存储端保留，不接受后续 upsert 对它的覆盖。读取旧记录时以有效 `updatedAt` 作为估算，标记 `createdAtEstimated: true`；首次写回即持久化该估算，不让之后的编辑继续推动它。
- 无有效旧时间则显示“加入时间未记录”，不凭空补为当前时间。旧记录的估算在界面显示“约”，悬浮明确说明原始加入时间未记录、依据旧版最后保存时间估算。
- 会话本地待办沿用其不可变 `heldAt`，不复制到清单存储。
- 保留 v1 文件、pending key 与原有回执幂等机制；新增时间字段可选，兼容旧客户端。

## 验收

- 回归：乱序输入的稳定升序投影；每类行的可见时间；pending 重载与确认不抖动；编辑/领取/退回后时间不变；旧数据估算/未知策略；无效时间拒绝。
- 运行 `npm run check` 和 `npm test`。更新注入版本，在真实面板验证排序、标签和操作，不发送任何用户任务。
