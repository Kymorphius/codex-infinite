# 最近发送会话入口

## 用户需求

在原生顶部“最近会话”旁增加“最近发送”，用于返回自己最近实际发送过消息的会话；原来的最近打开记录和当前打开页面语义不变。

## 行为与契约

- 两个入口相邻，复用相同菜单样式。“最近会话”和“最近发送”均最多提供 40 个会话，与最近打开历史的保存上限一致；“最近发送”按最后一条有效用户输入时间倒序，每个会话仅一项，显示发送时间。关闭时不预渲染行；打开时先渲染 12 条，滚动接近底部时每次追加至多 12 条，首批不足以填满菜单时继续填充至可滚动或全部展示。只监听菜单自身滚动，不新增轮询或 DOM 观察器。
- 发送时间来自本机 Codex 的只读 session 记录，排除环境/AGENTS 注入、委派输入、助手和工具输出；不得以 updatedAt、文件 mtime、创建或打开时间代替。
- 当前版本仅包含既有任务索引中的非归档、非子代理本机会话。不具有可信发送时间的 ChatGPT/远端会话不列入，入口提示注明范围。
- 冷索引后台读取，保留加载状态；读取失败保留已有结果并标明未刷新。最新用户记录位于大文件中段时也不能用首尾截取误判。
- 点击记录通过现有原生会话导航打开，包括尚未出现在最近打开记录中的会话；独立窗口按钮沿用原生窗口路径。
- 发布给界面的仅有会话 ID、标题、发送时间；不包含消息正文或源文件路径。

## 实现边界与性能

- 新增只读发送时间索引和服务，消费 task adapter 已有缓存快照，不再递归遍历目录或额外调用 listTasks。
- 大文件读取在后台、有限并发，缓存文件指纹/扫描进度；已有文件只追加读取。记录解析内存有上限，不阻塞现有任务索引和注入。
- 复用已有注入同步周期推送规范化快照；前端不增加定时器或 MutationObserver。
- 关闭的菜单不重建内容，相同快照不改动 DOM；菜单展开后按真实变化刷新。
- 本地只缓存时间元数据，不修改原生会话，也不自动发送消息。

## 验证

- 时间索引：有效用户输入/排除项、追加、无换行的未完成记录、重复/损坏记录、超大中段、文件替换/截断和不变文件缓存。
- 服务：无额外任务扫描、后台不阻塞、失败保留、归档和子代理排除、稳定倒序/去重/限额。
- 菜单：相邻入口、时间顺序、未打开会话导航、独立窗口、空/加载态、关闭和相同快照零 DOM 重建。
- 运行 npm run check、npm test；重载本地伴随服务。实际原生 UI 若因工具权限无法验证，明确保留验收限制。

## 本轮验证记录

- `npm run check`：489 个语法检查文件、521 个结构检查文件通过，无预算调整。
- `npm test`：876 项通过，包含 25 项新回归（索引、服务、菜单运行时与注入接线）。
- 菜单 VM 验证同快照保留行节点，关闭时数据更新不重建内容；服务后台更新不反复切换加载态。
- 本地增强服务已按原 launchd 配置重载，未重启原生 Codex，也未发送或修改任何用户会话。
- 原生窗口受本会话桌面自动化访问限制，未进行实际窗口点击验收；代码/运行时模拟测试不等于原生 UI 验收。
- 超过记录解析上限且不能确认是非用户记录、损坏或尚未完整写入的记录按未知处理，保留旧结果并显示未刷新，不用较早时间冒充最新时间。
