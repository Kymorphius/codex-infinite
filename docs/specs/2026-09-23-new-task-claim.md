# 新建任务页领取任务并创建会话

## 背景

统一任务面板之后，已有会话中的入口显示“领任务”，新建任务页因为尚无会话 ID 仍显示“指派任务”，点开也是指派模式。用户明确要求新建页领取后用该任务内容创建一个新会话。

## 行为

- 新建任务页入口显示“领任务 N”，N 为当前未指派且未完成的综合任务数。点开共用面板的领取视图，只列出可领取任务，保留搜索、原位编辑与加入时间。
- 领取读取用户点击时该项编辑框的最新内容，写入新任务页的原生输入框，触发原生发送创建会话。新建页这条任务直接执行；已有会话的领取仍放入暂停待办。
- 只定位新任务输入框内明确的原生发送按钮，不另开 app-server，也不代替原生编辑器处理发送。核对新会话 ID、创建时间及第一条用户消息与领取文本一致后，把原任务按同一 ID 标记为已完成并关联新会话。任务 ID 与最初加入时间不变，不再作为未发送待办重复出现。
- 如果插入/发送前失败，不更新原任务；发送后的结果不确定时保留原任务并提示用户检查新会话，避免重复点击。点击期间防重入。
- 旧会话仍直接领到当前会话。新建页不得把侧栏残留选中项当作新会话 ID。

## 状态与边界

- 继续使用综合清单原本的任务 ID、`assignedThreadId` 和带回执的待保存操作，没有另建任务副本或另一套待办权威状态。
- 仅为这一操作查询刚创建的会话第一条消息；不扩大全局队列桥接方法、不新增常驻轮询或观察器。
- 服务端保存确认前保留本地待保存操作；如果会话已创建但任务保存失败，显示错误并允许后续同步恢复，绝不再自动发送一次。
- 现有注入版本需更新，以替换热运行中的旧按钮闭包。

## 验证

- 新建页按钮与面板均为领取，现有会话仍领取；无会话时不回落至指派。
- 输入框未失焦编辑、已有草稿保护、原生按钮不可用、消息不匹配、创建失败/无效 ID、保存失败、快速重复点击、路由变化及热升级。
- 新建页只有一次原生发送；已有会话仍保持暂停领取；任务 ID 和加入时间不变。
- 运行 `npm run check` 与 `npm test`，重载本地伴随服务。原生 UI 若受桌面工具权限限制，单独记录未验收。
