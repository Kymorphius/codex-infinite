# 原生 GPT 实际推理强度与传输观测

## 目标

仅当路由因模型不支持所选推理档位而调整时，在当前会话模型按钮旁显示
`推理 ultra → high`，悬停解释为模型支持范围调整。字段描述路由实际发送的
参数，不声称服务器证明了模型内部计算强度。不修改用户模型设置。

正常档位、切换会话、路由不可用或缺少可信观测时不显示。按会话中最新请求
选择记录，包括正在请求且尚未收到响应头的情况；新请求没有调整必须清除旧提示。
不用历史上最近一次有 turn state 的请求代替最新请求。

## 数据与边界

Router activity 增加 requestedReasoningEffort、effectiveReasoningEffort，以及
nativePreparationMs、nativeRequestBytes、nativeUploadBytes。仅固定档位与非负数，
不含请求正文、命令、认证或 turn state 内容。控制台复用已有鉴权 activity 读取，
由适配器标准化后传给注入 UI。旧路由缺少字段时向后兼容。

准备时间仅指 HTTP 请求处理器内的接收、解析、规范化和压缩，到发送上游前结束；
不含更早的 WebSocket 历史重建、首次编码、内部转发，也不含上游生成时间。
字节数分别为解压后的原始请求与实际压缩上传体，不能当作 token 或计费节省。

## 传输阶段

本阶段先提供可观测基线并检查可安全减少的本地处理。保留现有工具结果精简，
不直接启用上游增量续接：历史精简会改变前缀，必须证明上游续接状态与重写历史一致。
续接大小检查使用 UTF-8 字节计数代替创建仅为读取长度的 Buffer，减少一次完整历史
字节缓冲区分配；边界与上下文恢复不变，不声称减少上游上传字节或首字延迟。
不自动重启正在承载会话的 Router。不消费真实模型额度做基准。

## 验收

- 档位相同或字段无效时不出现提示；不同档位显示真实参数差异。
- 活跃请求、结束请求、线程切换、不可用状态的更新与清除正确。
- activity 只输出白名单元数据；旧字段与旧 Router 保持兼容。
- 单测、控制台 check/test 与 Router 相关集成测试通过。
- 真实窗口验收与代码/模拟验证分别记录；未加载的代码不宣称已生效。

## 当前验证证据

- 档位调整、无响应头活跃请求、正常请求清除、切换会话和不可用状态的回归通过。
- Chromium 模拟页面已渲染提示并验证清除；实际桌面窗口尚未加载本次 Router 数据字段。
- 本地模拟上游验证实际请求档位与 activity 对应，未知档位不进入公开观测字段。
- WebSocket UTF-8 恰好上限与超限一字节，以及原有恢复/压缩重试测试通过。
- 合成约 2 MB 历史避免约 2 MB Buffer 分配；计时有波动，未证明端到端响应更快。
