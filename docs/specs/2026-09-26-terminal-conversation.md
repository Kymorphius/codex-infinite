# 终端会话与底部输入控制台

## 目标

用户希望终端成为会话界面：上部显示原生 CLI 的完整执行过程，下部提供类似现有会话的输入控制台；会话内始终能直接操作完整终端。底部输入和终端键盘连接同一个 PTY，不转发到 Codex，也不重建 Claude 的执行循环。

## 界面与行为

- 终端入口呈现占满可用高度的会话工作区：会话选择、精简标题/目录/连接状态、可直接交互的 xterm、始终可见的底部输入框。
- 每个终端会话有独立草稿，切换会话不串内容；草稿仅存在当前页面内存，退出页面不宣称持久保存。
- 底部支持多行编辑、中文输入法、Enter 发送、Shift+Enter 换行，提供发送、仅粘贴到终端、打断（Ctrl+C）、聚焦终端等真实操作。
- 发送使用 xterm 的粘贴语义，将文本交给当前程序，再向同一连接发送 Enter。禁止在断线/回放未完成/进程退出/连接被接管时写入；失败保留草稿，不自动重放输入。用户需按终端所处程序/提示决定输入内容，界面不猜测 Claude 是否正在生成。
- 下部发送仅接受普通文本（换行、Tab 可用），不注入 ESC 或其他控制字符。原生终端键盘不做这种限制，继续支持 Ctrl+C、Ctrl+D、Tab、方向键、全屏程序、Shell 命令等。
- 多行文本仅在终端已启用 bracketed paste 时支持底部发送；否则提示先使用终端直接输入，避免多行被当成多个立即执行的命令。
- 不自动清除终端已有输入，不截获授权选择；提供聚焦终端与单独 Enter/Esc 操作以继续原生交互。
- Claude 会话中可按同一工作目录新建 Shell，原有 Claude 进程继续保留。现有 Shell/Claude 多会话切换、尺寸适配、关闭确认、刷新恢复及有界输出保持有效。
- 不显示不能真实操作的 Codex 模型、推理和队列控件；Claude 自有设置与权限提示仍在原生 CLI 中操作。
- 按用户提供的 ChatGPT 截图，将底部改为一体大圆角输入卡：控件在卡内底部，左侧加号与胶囊操作，右侧会话类型及圆形发送按钮；完整终端操作收进加号菜单，终端本身仍可直接操作。

## 项目与会话入口

- 项目目录的每个本机、已连接的具体目录提供“终端会话”入口；会话中心的本机目录分组提供相同入口。远端和无真实本机路径的项目不按本机处理。
- 入口传递 `{provider:'terminal',cwd,projectName}`，打开后按精确启动目录筛选终端，会话名称和新建工作目录继承项目上下文。不同路径即使同名也不合并。
- 深链 `?module=terminal&session=<id>` 只定位现有会话。不存在、已关闭或不属于指定目录时显示提示，不自动创建替代会话，也不将 PTY ID 当成 Codex 原生会话 ID。
- 父页面未来可通过专用 `codex-control-console-open-terminal-conversation` 消息使用相同入口；仅接受父窗口且来源为 `app://-`。本次接通浏览器端适配，未宣称安装了新的原生侧栏注入器。

## 边界

- 复用现有 PTY/WebSocket，不新增进程协议、不改变 Origin/Host 校验，不改服务生命周期、凭证和运行数据。
- 本次接通项目目录、会话中心与终端工作区的导航，不伪造 Codex 原生任务记录。原生侧栏自动发现、归档和跨重启恢复仍需独立的会话元数据/生命周期设计；PTY 存活不等于模型正在生成。
- 本次仅修改已允许提供的浏览器资源，刷新页面应用更新，不重启后台或终止已交付的 Claude 会话。
